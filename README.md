# Прогноз риска задержки доставки: сегментация клиентов + CatBoost

Система поддержки принятия решений для логистического оператора CargaPronto (Пуэрто-Рико → США): в момент оформления заказа модель оценивает вероятность нарушения SLA и подсвечивает диспетчеру высокорисковые заказы для смены приоритета сборки или режима доставки.

**Бизнес-контекст:** 55% заказов уходят с задержкой, штрафы за SLA превысили бюджет на IT, крупные ритейлеры угрожают расторжением контрактов. Гипотеза заказчика — задержки коррелируют не с логистикой, а с профилем клиента (география + поведение).

## Данные

Две таблицы: ~65 тыс. заказов и ~20 тыс. уникальных клиентов. Признаки заказа — режим доставки, категория, цена, дата/время; профиль клиента — координаты + RFM (`recency`, `total_orders`, `total_sales`, `avg_discount`, `return_rate`). Целевая переменная — бинарная метка задержки.

## Подход

- **Аудит данных:** проверка целостности связей `customers ↔ orders`, удаление «заказов-сирот», фильтрация географических аномалий (GPS-шум за пределами региона США/Пуэрто-Рико).
- **Split без утечек:** `GroupShuffleSplit` по `customer_id` в пропорции 60/20/20 — заказы одного клиента не разлетаются по train/val/test.
- **EDA:** корреляции через **phik** (корректно работает со смешанными типами), баланс классов, проверка распределений признаков.
- **Baseline:** LogReg (ElasticNet) и CatBoost на «сырых» признаках заказа — фиксация точки отсчёта до кластеризации.
- **Гео-сегментация:** K-Means++ на координатах, K подобран методом локтя (K=9); Scaler и K-Means обучаются только на train-клиентах.
- **Поведенческая сегментация:** K-Means++ на 5-мерном RFM-векторе (K=8), визуализация t-SNE, содержательный разбор кластеров («лояльные экономные», «новички с высоким риском» и т.п.).
- **Финальная модель:** CatBoost + `geo_cluster` и `beh_cluster`; дополнительно — совместный подбор `geo_k` и `beh_k` как гиперпараметров всей системы.
- **Интерпретация:** SHAP (summary + waterfall), матрица ошибок, важность признаков.

## Результаты

| Модель | Выборка | ROC-AUC |
|---|---|---|
| LogReg baseline | val | 0.732 |
| CatBoost baseline | val | 0.805 |
| CatBoost + кластеры | val | **0.810** |
| **CatBoost + кластеры** | **test** | **0.801** |

Целевой порог **0.75 на тесте уверенно достигнут**. Спад val → test минимальный (0.810 → 0.801) — модель не переобучилась.

Ключевые выводы:

- **Гипотеза заказчика подтвердилась частично.** Поведенческий сегмент (`beh_cluster`) вошёл в топ-3 признаков по SHAP; географическая сегментация дополнительного сигнала почти не принесла — гео-зоны полезны скорее для планирования маршрутов, чем для риск-скоринга.
- **Главные драйверы риска** — `shipping_mode` и `order_hour`; цена товара и категория практически не влияют. Ускоренные режимы доставки (Same Day, First Class) модель справедливо считает более «опасными» из-за жёсткого SLA.
- **Технический инсайт:** передача `order_hour/weekday/month` в CatBoost как `cat_features` подняла baseline на ~0.01 ROC-AUC, хотя phik оценивал связь часа с таргетом как слабую (~0.07) — линейные метрики зависимости недооценивают вклад признаков в древесные модели.
- **Баланс ошибок:** при пороге 0.5 модель чаще пропускает задержки (recall класса 1 ≈ 0.58, precision ≈ 0.86) — для минимизации штрафов SLA порог можно снизить, приняв больше ложных эскалаций.

## Стек

Python, pandas, scikit-learn (`GroupShuffleSplit`, K-Means, t-SNE), CatBoost, phik, SHAP, Optuna, matplotlib/seaborn, folium.

## Запуск

```bash
pip install -r requirements.txt
```

Открыть `main.ipynb` и выполнить ячейки по порядку. Данные подтягиваются по HTTPS при первом запуске; для локального URL создать `.env` по образцу `.env.example`.
